# EvidenceDesk: с чего начать

Это учебный backend для поиска ответов в текстовых документах. Он возвращает точные выдержки с версией документа и номерами строк. По умолчанию используется BM25: приложение работает без модели, внешнего API и платного аккаунта.

## Быстрая проверка

Нужен **Node.js 24.12.0 или новее в ветке 24.x**. Выполняй команды из папки проекта:

```bash
node --version
npm test
npm run evaluate
npm run demo
```

Для этих команд `npm install` не нужен: runtime-зависимостей нет. Демо временно запускает HTTP-сервер, загружает три вымышленных справочника, показывает ответ со ссылками на строки и отказ при отсутствии подходящих данных, затем завершает работу.

Node выполняет TypeScript, удаляя аннотации типов, но не проверяет типы. Для отдельной проверки установи зафиксированные зависимости разработки:

```bash
npm ci
npm run typecheck
```

## Постоянный локальный сервер

```bash
cp .env.example .env
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

В PowerShell вместо первой команды используй `Copy-Item .env.example .env`. Скопируй сгенерированное значение в `EVIDENCE_API_TOKEN` внутри `.env`, заменив пример целиком. Затем:

```bash
npm start
```

Адрес сервера — `http://127.0.0.1:8787`, файл базы — `var/evidence.sqlite`. Токен нужен в заголовке `Authorization: Bearer <твой токен>` для всех маршрутов, кроме `/health`. Не публикуй `.env`. Примеры HTTP-запросов находятся в [README.md](README.md).

## Что важно понимать

- Это MVP с одним общим рабочим пространством и токеном. Нет авторизации отдельных пользователей, мультитенантности и шифрования базы. Синхронные операции SQLite и пересчёт статистики поиска рассчитаны на небольшие корпуса.
- Лексическое совпадение не доказывает ответимость вопроса. Синонимы, отрицания, числовые рассуждения и разные языки обрабатываются ограниченно; похожий по словам, но неподходящий отрывок может попасть в ответ. Поддерживаются только текст и Markdown.
- Неизменяемые версии позволяют проверять старые цитаты после редактирования; удаление документа удаляет его версии и цитаты. SSE передаёт уже вычисленный результат, а не токены модели в реальном времени.
- Необязательный Ollama выбирает готовые выдержки, а не пишет ответ. Реальная модель и её качество здесь не оценены; адаптер проверяется с подставным HTTP-провайдером. Документы при этом режиме отправляются на настроенный адрес модели.
- В README зафиксирован локальный результат **Recall@3 = 1.00, MRR@3 = 1.00, точность отказа = 1.00** на **10 ответимых и 2 посторонних вопросах**. Это маленький синтетический **dev-set**, по которому уже улучшали токенизатор, а не независимая проверка и не «100% точность ИИ». Твой запуск `npm run evaluate` покажет результат текущей версии. Docker и размещённый CI в описанной среде не проверены.

## Пять вопросов для подготовки к собеседованию

1. Как BM25 ранжирует выдержки и почему высокая оценка не гарантирует, что текст отвечает на вопрос?
2. Как версия документа, хеш и номера строк сохраняют проверяемость цитаты после изменения исходного текста?
3. Как `BEGIN IMMEDIATE` и `expectedRevision` предотвращают потерю параллельных изменений и когда API возвращает 409?
4. Почему ограничение ответа модели индексами выдержек уменьшает риск подмены ответа, но не гарантирует достоверность источника?
5. Как собрать независимый набор проверки с трудными отрицательными примерами и что измерить перед увеличением корпуса?

## Как честно представить проект

Называй его **учебным портфолио-проектом, подготовленным с помощью ИИ**. Разделяй сгенерированную основу и свой подтверждённый вклад: какие участки ты лично разобрал, какие изменения сделал, какие команды запустил и какие результаты увидел. Если этого ещё не делал, не приписывай себе проверку или самостоятельную разработку.

После практики можно использовать формулировку: «Основа проекта подготовлена с помощью ИИ. Мой личный вклад — [конкретное выполненное изменение]. Я проверил [реально выполненный сценарий] и могу объяснить [разобранное решение]». Подставляй только проверенные факты. Не заявляй коммерческую эксплуатацию, production-развёртывание или большую нагрузку без такого опыта. Для разбора реализации начни с [ARCHITECTURE.md](ARCHITECTURE.md).
